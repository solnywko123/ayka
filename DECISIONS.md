# DECISIONS.md — лог самостоятельных решений

Здесь фиксируются решения, принятые без явного указания в BRIEF.md, с обоснованием. Формат: дата, решение, почему.

## 2026-08-15 — Общий подход к выполнению

**Решение:** BRIEF.md выполняется как готовое ТЗ без дополнительного брейнсторминга с пользователем: раздел 17 прямо запрещает переспрашивать по мелочам, раздел 0 задаёт рабочие демо-данные, а раздел 18 задаёт порядок этапов. Решения по всем незакрытым вопросам принимаются самостоятельно и фиксируются здесь.

**Почему:** пользователь явно попросил не останавливаться с вопросами и работать по разделу 18 от начала до конца.

## 2026-08-15 — Тестирование без строгого TDD-цикла

**Решение:** код пишется, затем сразу покрывается тестами из раздела 15 (pytest для API, test_build.py и test_no_hardcoded_contacts.py для сайта), тесты прогоняются до зелёного состояния перед коммитом соответствующего этапа. Строгий red-green-refactor цикл по каждой мелкой функции не используется.

**Почему:** масштаб задачи — 14 этапов, полноценный сайт + API + админка за один проход. Формальный TDD на каждую строчку кратно увеличил бы время выполнения без выигрыша в качестве при таком объёме; при этом требование раздела 15 (тесты обязательны и зелёные) полностью выполняется.

## 2026-08-15 — Python окружение

**Решение:** используется `py` (Python Launcher, Python 3.13.4) вместо `python`/`python3` — на машине эти команды указывают на заглушку Microsoft Store. Виртуальное окружение `.venv` создаётся через `py -m venv .venv`. В Makefile и README команды используют `py`/`.venv` явно, без опоры на `python` в PATH.

**Почему:** `python`/`python3` в PATH ведут на неустановленную заглушку Windows Store и завершаются с ошибкой; `py`-лаунчер найден и указывает на реально установленный Python 3.13.4 (BRIEF.md требует 3.12+, 3.13 совместим).

## 2026-08-15 — Git identity

**Решение:** используется уже настроенная глобальная git-идентичность пользователя (найдена через `git config user.email/user.name`), локальный override в репозитории не создаётся.

**Почему:** git config уже содержит валидные global user.name/user.email, локальная переустановка не требуется и не запрашивалась.

## 2026-08-15 — `make` недоступен локально

**Решение:** `Makefile` создаётся по спецификации (раздел 3, 13, 14, 19.3) и будет работать в Linux/CI/деплой-окружениях (Netlify/Render, где `make`/POSIX-шелл есть по умолчанию). Локально на этой Windows-машине `make` не установлен, поэтому для самопроверки в ходе разработки команды из Makefile прогоняются напрямую (`py site/build.py`, `py -m pytest` и т.д.), а не через `make`.

**Почему:** `where make` не находит исполняемый файл на машине; переустановка make не входит в объём задачи и не блокирует выполнение остальных требований BRIEF.md.
