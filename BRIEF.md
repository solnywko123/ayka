## 1. ЦЕЛЬ ПРОЕКТА

Сайт — **инструмент продаж**, а не визитка. Главная метрика — количество заявок (лидов) в месяц. Всё остальное подчинено этому.

Целевые действия по приоритету:
1. Нажатие «Рассчитать стоимость» → калькулятор → отправка заявки.
2. Клик по WhatsApp (в Кыргызстане это основной канал).
3. Клик по телефону (мобильные).

Требования к результату:
- Lighthouse (mobile): Performance ≥ 90, SEO = 100, Accessibility ≥ 95, Best Practices ≥ 95.
- Первый экран (LCP) < 2.0 с на 4G.
- Форма заявки доступна с любой страницы максимум в 1 клик.
- Сайт корректно работает при 360px ширины (мобильный трафик в KG — 80%+).

## 2. АРХИТЕКТУРА И СТЕК

**Строго придерживаться. Никаких React/Next/Vue/WordPress.**

**Frontend:** статические HTML-страницы, генерируемые Python-скриптом `build.py` (Jinja2) из JSON-контента.
- Ванильный CSS (без Tailwind/Bootstrap), CSS custom properties, современный layout (grid/flex, `clamp()`).
- Ванильный JS (ES modules), без jQuery и без сборщиков (webpack/vite не нужны).
- Никакого CSS/JS с CDN в проде — всё локально.

**Backend:** Python 3.12 + FastAPI + SQLAlchemy 2.0 + Pydantic v2.
- БД: SQLite для локальной разработки, PostgreSQL в проде — переключение через `DATABASE_URL`.
- Миграции: Alembic.
- Сервер: uvicorn, в проде под gunicorn с uvicorn workers.

**Почему статика, а не SSR:** максимальный SEO, нулевая стоимость хостинга фронта, невозможно уронить сайт падением бэкенда. Если API недоступен — сайт продолжает работать, форма деградирует до кнопки WhatsApp.

## 4. ДИЗАЙН

**Не делай «типовой AI-лендинг».** Нужен вид опрятного сервисного бизнеса, которому доверяют деньги и ключи от квартиры.

**Визуальное направление:** чистый, светлый, воздушный. Много белого пространства. Ощущение свежести и порядка.

**Палитра** (задай через CSS-переменные, оттенки подбери сам в этом направлении):
- Основной: глубокий сине-зелёный / бирюзовый (ассоциация с водой и чистотой), НЕ ядовитый.
- Акцент для кнопок: тёплый контрастный (например мягкий оранжевый/коралловый) — CTA должны выделяться.
- Нейтральные: тёплый белый фон, мягкий серый для текста (не чистый #000).
- Обязательно поддержи `prefers-color-scheme: dark` — но светлая тема основная.

**Типографика:** одна гарнитура с хорошей кириллицей (Inter / Manrope / Onest), self-hosted `.woff2`, `font-display: swap`. Крупные заголовки (`clamp(2rem, 5vw, 3.5rem)`), body ≥ 17px, line-height 1.6.

**Компоненты:** мягкие скругления (12–16px), тонкие тени, аккуратные ховеры с `transition`. Никаких резких градиентов, никаких стоковых иллюстраций в стиле «люди-морковки».

**Изображения:** используй плейсхолдеры (сгенерируй SVG-заглушки нужных размеров с подписью, что заменить), укажи в README точные размеры и что снимать. Никаких чужих фото из интернета.

**Анимации:** только `IntersectionObserver` fade-in при скролле, максимум 300ms, обязательно `prefers-reduced-motion: reduce` → отключить.

## 6. КАЛЬКУЛЯТОР СТОИМОСТИ

Ключевой элемент конверсии. Логика в `pricing.json` — **единый источник правды для фронта и бэка**, дублировать формулы нельзя.

**Поля:**
1. Тип уборки (4 карточки-радио с иконками)
2. Тип объекта: квартира / дом / офис
3. Площадь, м² — слайдер (20–300) + числовое поле, синхронизированы
4. Количество санузлов (1–5)
5. Доп. услуги — чекбоксы с количеством (окна — створок, диван — мест, ковёр — м²)
6. Срочность: в течение недели / сегодня-завтра
7. Регулярность: разово / раз в месяц / раз в 2 недели / еженедельно

**Поведение:**
- Цена пересчитывается мгновенно на клиенте, без перезагрузки, с анимацией счётчика.
- Результат: «Ориентировочно **12 400 – 14 300 сом**» + строка «≈ 4 часа работы, 2 клинера».
- Показывать экономию при регулярной уборке: «Вы экономите 1 800 сом при еженедельной уборке».
- Кнопка «Вызвать клинера» → форма заявки, все параметры калькулятора переносятся автоматически.
- Формула на бэкенде (`api/app/pricing.py`) пересчитывает независимо при сохранении заявки — клиенту не доверяем.

**Формула:**
```
base       = area_m2 * base_rate[service_type]
base      += bathroom_extra * max(0, bathrooms - 1)
addons_sum = Σ(addon_price * qty)
subtotal   = (base + addons_sum) * property_multiplier * urgency_multiplier
subtotal   = subtotal * (1 - frequency_discount)
total      = max(subtotal, min_order)
price_min  = round(total * (1 - spread), -1)
price_max  = round(total * (1 + spread), -1)
```

## 7. BACKEND API

Базовый путь `/api/v1`. Ответы в JSON, ошибки — единый формат `{"error": {"code": "...", "message": "..."}}`.

| Метод | Путь | Описание | Доступ |
|---|---|---|---|
| GET | `/health` | liveness + проверка БД | public |
| GET | `/pricing` | отдаёт актуальный `pricing.json` | public |
| POST | `/quote` | расчёт цены по параметрам | public, rate-limit |
| POST | `/leads` | создание заявки | public, rate-limit |
| POST | `/admin/login` | вход, выдаёт JWT в httpOnly cookie | rate-limit 5/мин |
| POST | `/admin/logout` | | admin |
| GET | `/admin/leads` | список: фильтры по статусу/дате/услуге, поиск по телефону, пагинация | admin |
| GET | `/admin/leads/{id}` | карточка заявки | admin |
| PATCH | `/admin/leads/{id}` | смена статуса, заметка, ответственный | admin |
| GET | `/admin/leads/export.csv` | выгрузка с фильтрами (UTF-8 BOM для Excel) | admin |
| GET | `/admin/stats` | заявки по дням, конверсия по статусам, разбивка по UTM | admin |

**Валидация заявки:**
- `name`: 2–100 символов
- `phone`: нормализовать к `+996XXXXXXXXX`, принимать форматы `0555...`, `996...`, `+996 555 12-34-56`
- `area_m2`: 5–1000
- `preferred_date`: не в прошлом, не дальше 90 дней
- `comment`: до 1000 символов, санитизация HTML

**Антиспам (без капчи — она режет конверсию):**
1. Honeypot-поле `company_website`, скрытое CSS. Заполнено → тихо возвращаем 200, в БД пишем `status='spam'`.
2. Time-trap: форма отправлена быстрее 3 секунд после рендера → `status='spam'`.
3. Rate limit по IP: 5 заявок/час, 30 `/quote`/мин (slowapi).
4. Блок-лист повторяющихся текстов.

**Безопасность:**
- CORS — только домен сайта, из ENV.
- Пароль админа — только bcrypt-хеш в ENV (`ADMIN_PASSWORD_HASH`), скрипт `make hash-password` для генерации.
- JWT: httpOnly + Secure + SameSite=Lax, TTL 12 часов.
- Security-заголовки: CSP, X-Content-Type-Options, Referrer-Policy, HSTS.
- IP хранить только как SHA-256 хеш с солью (персональные данные).
- Никаких секретов в git. `.env.example` со всеми ключами и комментариями.

## 10. SEO — ОБЯЗАТЕЛЬНЫЕ ТРЕБОВАНИЯ

**На каждой странице:**
- Уникальные `<title>` (50–60 симв.) и `<meta name="description">` (140–160 симв.), из JSON-контента, а не сгенерированные шаблоном.
- Ровно один `<h1>`, корректная иерархия h2/h3.
- `<link rel="canonical">` с абсолютным URL.
- `hreflang` для ru/ky/en + `x-default` → ru.
- Open Graph + Twitter Card, OG-изображения 1200×630 генерировать скриптом на этапе сборки.
- Семантические теги: `header/nav/main/article/section/aside/footer`.
- Все изображения с осмысленным `alt`, `width`/`height`, `loading="lazy"` (кроме hero — `fetchpriority="high"`).

**JSON-LD:**
- `LocalBusiness` (подтип `HomeAndConstructionBusiness`) на всех страницах: name, image, telephone, address, geo, openingHoursSpecification, priceRange, areaServed, sameAs.
- `Service` + `Offer` на страницах услуг.
- `FAQPage` там, где есть FAQ.
- `BreadcrumbList` на всех вложенных страницах.
- `Article` в блоге.
- `AggregateRating` — **только при реальных отзывах** (см. 5.1 п.6).

**Технические файлы:**
- `sitemap.xml` — генерируется, с `lastmod` и hreflang-альтернативами.
- `robots.txt` — открыт для индексации, `Disallow: /admin`, ссылка на sitemap.
- `.htaccess`/заголовки: 301 с `www` на без-`www` (или наоборот), обязательный HTTPS-редирект, единообразный слеш в конце URL.
- Кастомная 404.
- Скорость: критический CSS инлайном в `<head>`, остальное отложенно; preload шрифтов; WebP/AVIF; brotli-сжатие на хостинге.

**Ключевые слова** (собери в `content/ru/seo.json`, распредели по страницам, без переспама — плотность до 2%):
`клининг Бишкек`, `уборка квартир Бишкек`, `генеральная уборка Бишкек цена`, `уборка после ремонта Бишкек`, `клининговая компания Бишкек`, `уборка офисов Бишкек`, `химчистка дивана Бишкек`, `мытьё окон Бишкек`, `тазалоо кызматы Бишкек` (ky), `cleaning services Bishkek` (en).

## 19. ПЛЕЙСХОЛДЕРЫ И НАСТРОЙКА ВЛАДЕЛЬЦЕМ

Контакты и цены будет заполнять владелец бизнеса — человек без технических навыков. Спроектируй это так, чтобы он не смог ничего сломать.

**19.1 Единая точка правки.** Все данные компании — только в `site/content/config.json`. Все цены — только в `site/content/pricing.json`. Ни один телефон, адрес, email, ссылка или число из прайса не должны встречаться нигде больше: ни в шаблонах, ни в CSS, ни в JS, ни в коде API, ни в тестах (в тестах — через фикстуры).

**19.2 Проверка на захардкоженные значения.** Добавь тест `site/tests/test_no_hardcoded_contacts.py`: рекурсивный grep по `templates/`, `static/`, `api/app/` на паттерны `+996`, `@example`, `wa.me/`, `example.kg`. Найдено вне `config.json` → тест падает.

**19.3 Валидатор конфига.** Скрипт `make check-config` (он же `site/check_config.py`):
- сверяет `config.json` со схемой (обязательные поля, формат телефона, валидность URL);
- отдельно печатает список полей, оставшихся демонстрационными (`+996 700 000 000`, `example.kg`, `info@example.kg`);
- в режиме `BUILD_ENV=dev` — печатает жёлтое предупреждение и продолжает сборку;
- в режиме `BUILD_ENV=prod` — **прерывает сборку** с понятным сообщением: какие именно поля надо заполнить и в каком файле. Это защита от выкатки в прод с телефоном `700 000 000`.

**19.4 Баннер демо-режима.** Пока в конфиге остались плейсхолдеры и `BUILD_ENV=dev` — выводить наверху страницы неубираемую жёлтую полосу: «Демо-версия. Контакты и цены не настроены». В прод-сборке баннера нет по определению, потому что она не соберётся с плейсхолдерами.

**19.5 Инструкция для владельца.** Файл `НАСТРОЙКА.md` в корне — на русском, без технического жаргона, для человека, который открывает файл в Блокноте:
- где лежит файл с контактами и где с ценами;
- что означает каждое поле, с примером заполнения;
- что нельзя удалять кавычки и запятые;
- как проверить, что не сломал (`make check-config`);
- как выкатить изменения (git push → автодеплой);
- отдельный короткий раздел «Как поменять цены» — самая частая операция.

**19.6 Цены и калькулятор.** После правки `pricing.json` калькулятор на сайте и расчёт на бэкенде должны измениться без единой правки кода. Бэкенд читает тот же файл — либо из общего пути, либо через переменную `PRICING_PATH`, но не копией. При старте API логировать хеш загруженного прайса, чтобы было видно, какая версия цен активна.

**19.7 Что владелец обязан заполнить до запуска рекламы** (вынести в конец `НАСТРОЙКА.md` чеклистом): телефон и WhatsApp, домен, email, часы работы, реальные цены, минимум 5 настоящих фото своих работ, реальные отзывы, ID Google Analytics и Яндекс.Метрики, пароль админки. До этого момента запускать платный трафик нельзя — деньги уйдут впустую.
